# הסעות לחתונה — דף הרשמה

דף נחיתה אחד (`index.html`) שמתארח ב-GitHub Pages בחינם, ושולח כל הרשמה
לשורה חדשה בגוגל שיטס דרך Google Apps Script. אין שרת, אין מסד נתונים, אין עלות.

```
אורח → index.html (GitHub Pages) → Apps Script Web App → Google Sheet
```

---

## שלב 1 — התמונה והתוכן

1. שימו את התמונה שלכם בתיקייה הזו בשם `hero.jpg`.
   (אם היא `.png`, שנו גם את `heroImage` בשלב הבא.)
2. פתחו את `index.html` ועדכנו **רק** את בלוק `CONFIG` שבתחילת ה-`<script>`:

| שדה | מה לשים |
|---|---|
| `coupleNames` | שמות החתן והכלה |
| `eventDate` | התאריך כפי שיוצג |
| `venue` | שם האולם והעיר |
| `heroImage` | `'hero.jpg'` — או כתובת מלאה לתמונה |
| `locations` | רשימת תחנות העלייה, לפי הסדר שיוצג |
| `returnNote` | שעת היציאה המשוערת של ההסעה חזור |
| `endpoint` | נמלא בשלב 3 |

כל עוד `endpoint` ריק, הדף במצב תצוגה מקדימה: הטופס עובד אבל שום דבר לא נשמר,
ומופיע באנר שמסביר את זה. ברגע שתמלאו את הכתובת — הבאנר נעלם וההרשמות נשמרות.

---

## שלב 2 — הגיליון והסקריפט

1. צרו גיליון חדש ב-[sheets.new](https://sheets.new) וקראו לו למשל "הסעות לחתונה".
2. בגיליון: **תוספים ▸ Apps Script** (Extensions ▸ Apps Script).
3. מחקו את מה שיש שם, הדביקו את כל התוכן של `Code.gs` מהתיקייה הזו, ושמרו.
4. **Deploy ▸ New deployment**, ובחלון:
   - בגלגל השיניים שליד "Select type" בחרו **Web app**
   - *Execute as*: **Me**
   - *Who has access*: **Anyone** ← קריטי. בלי זה אורחים לא יוכלו להירשם.
5. אשרו את ההרשאות (יופיע מסך "Google hasn't verified this app" — לחצו
   *Advanced ▸ Go to ... (unsafe)*. זה הסקריפט שלכם, זה בסדר).
6. העתיקו את ה-**Web app URL**. הוא נראה ככה:
   `https://script.google.com/macros/s/AKfy.../exec`

> בדיקה זריזה: פתחו את הכתובת בדפדפן. אם חוזר `{"ok":true,...}` — הכול עובד.

---

## שלב 3 — חיבור

הדביקו את הכתובת ב-`endpoint` בתוך `index.html`:

```js
endpoint: 'https://script.google.com/macros/s/AKfy.../exec'
```

שורת הכותרת בגיליון נוצרת לבד עם ההרשמה הראשונה.

---

## שלב 4 — העלאה ל-GitHub Pages

1. צרו ריפו חדש ב-GitHub. **שם הריפו הוא חלק מהכתובת**, אז בחרו משהו
   שנוח לשלוח בוואטסאפ — למשל `hasaot` או `noa-itai`.
2. העלו את `index.html` ואת `hero.jpg` ל-**שורש** הריפו
   (אפשר בגרירה: *Add file ▸ Upload files*).
   את `Code.gs` ואת ה-README אפשר להעלות גם — הם לא מפריעים.
3. **Settings ▸ Pages**, ותחת *Source* בחרו **Deploy from a branch**,
   ענף `main`, תיקייה `/ (root)`. שמרו.
4. אחרי דקה-שתיים הכתובת תהיה:
   `https://<שם-המשתמש>.github.io/<שם-הריפו>/`

הריפו חייב להיות **Public** כדי ש-Pages יעבוד בחשבון חינמי.

## שלב 5 — בדיקה לפני ששולחים לאורחים

- [ ] נרשמתם פעם אחת בעצמכם מהנייד, ושורה הופיעה בגיליון
- [ ] התמונה נטענת (אם לא — השם של הקובץ לא תואם ל-`heroImage`)
- [ ] הבאנר "תצוגה מקדימה" **לא** מופיע
- [ ] מחקתם את שורת הבדיקה מהגיליון

## שינויים אחר כך

- **תחנה חדשה / שינוי שם תחנה** — ערכו את `locations` ושמרו. Pages מתעדכן תוך דקה.
  שימו לב: שינוי שם תחנה לא משנה הרשמות קיימות בגיליון.
- **איך נשאלת שאלת העדיפות** — הדף מתאים את עצמו לאורך `locations`:
  עם **שתי** תחנות מוצג סימון אחד, "גם התחנה השנייה מתאימה לי", ואם סומן
  נשמרת בעמודת "עדיפות שנייה" התחנה האחרת. עם **שלוש ומעלה** מוצג תפריט
  עדיפות שנייה, שחוסם בחירה כפולה באותה תחנה. בשני המצבים עמודות הגיליון
  זהות, אז מעבר מ-2 ל-3 תחנות לא שובר נתונים קיימים.
- **התצוגה המקדימה בוואטסאפ** — `preview.jpg` (1200×630) ותגיות ה-`og:` בראש
  `index.html`. התגיות מחזיקות כתובות **מלאות**, אז אם האתר יעבור לכתובת אחרת
  צריך לעדכן אותן שם. שימו לב שוואטסאפ שומר את התצוגה במטמון לפי כתובת: קישור
  שכבר נשלח ימשיך להראות את הישנה. הוספת `?v=2` בסוף הכתובת לא משנה כלום בדף
  עצמו, ומאלצת משיכה מחדש.
- **סגירת ההרשמה / פתיחה מחדש** — `registrationOpen` ב-`CONFIG`. `false` מוריד
  את הכפתור ומציג במקומו "ההרשמה להסעה נסגרה" עם פרטי הקשר; `true` מחזיר את
  הטופס. שורה אחת, הפיכה, והתמונה והפרטים נשארים על המסך.

  > **לא** לסגור דרך *Manage deployments ▸ Archive*. ארכוב הוא חד-כיווני: פתיחה
  > מחדש מחייבת deployment חדש עם **כתובת אחרת**, ואז צריך לעדכן גם את
  > `endpoint`. Archive מתאים רק כשבאמת סיימתם ולא תפתחו שוב.
- **כמה מקומות צריך בכל תחנה** — בגיליון: *נתונים ▸ יצירת טבלת ציר*, שורות =
  עדיפות ראשונה, ערכים = SUM של עמודת "מקומות". סכימה של העמודה הזו, ולא ספירת
  שורות, כי נרשם עם בן/בת זוג תופס שני מקומות בשורה אחת.
- **עמודות הגיליון** — חותמת זמן, שם פרטי, שם משפחה, טלפון, בן/בת זוג, מקומות,
  עדיפות ראשונה, עדיפות שנייה, הסעה חזור. עמודת "מקומות" נגזרת בסקריפט
  (1, או 2 אם מולא שם בן/בת זוג) ולא מגיעה מהדפדפן. עמודת הטלפון מוגדרת
  כטקסט, אחרת שיטס מפרש `0523403625` כמספר ומוחק את ה-0 שבהתחלה.
- **אחרי שינוי ב-`Code.gs`** — שתי פעולות, אחרת הכתובת ממשיכה להגיש את הקוד הישן:
  1. *Deploy ▸ Manage deployments ▸* ✏️ *▸ Version: **New version** ▸ Deploy*.
     הכתובת עצמה לא משתנה.
  2. אם השתנו העמודות: למחוק את לשונית "הרשמות" כולה (קליק ימני על הלשונית ▸
     מחיקה). הסקריפט בונה אותה מחדש עם הכותרות החדשות בהרשמה הבאה. בלי זה
     הכותרות הישנות נשארות והנתונים נכנסים לעמודות לא נכונות.

## מגבלות

Apps Script בחשבון גוגל רגיל מוגבל ל-20,000 קריאות ליום — יותר מדי לחתונה.
אין הגנה מפני הרשמות כפולות או מזויפות; הדף מיועד לקישור שנשלח לאורחים,
לא לאינטרנט הפתוח.
